# Panero 0.1.0 preview 10

**Panero is an independent fork of Krusader. It is not affiliated with or endorsed by KDE or the Krusader maintainers.**

Preview for **Zorin OS 18.1** and other **Ubuntu 24.04** based systems (x86_64).
It upgrades earlier previews in place; settings and cloud sign-ins are kept.

## Fix: freeze while browsing a cloud drive

Preview 9 could freeze (force quit needed) while browsing a cloud drive,
for example right after opening a few PDFs from OneDrive. While rclone is
busy, for example downloading files another program opened, or while it
re-reads a folder from the provider, every access to that folder waits for
it. Panero still made such accesses from its window's own thread:

- it changed its working directory into the folder you opened;
- it watched the folder for changes, which looked at every file in it;
- it looked for custom folder icons (`.directory`) in every folder shown;
- the folder tree checked icons and subfolders on the drive.

None of these happen on cloud drives any more. Panero's own copy, move and
delete still update the panel at once; changes made elsewhere appear through
the background check (within about 30 seconds) or with **Ctrl+R**.

Found with a new test that stops rclone entirely (every access to the drive
hangs) and then drives the window: before the fix, going up a folder froze
it; now no step waits for the drive.

## Fewer requests to Google Drive and OneDrive

For Google Drive, OneDrive, Dropbox and Box, Panero no longer makes rclone
re-read the folder you are looking at every 30 seconds: rclone already asks
these providers for changes every 30 seconds. The forced re-read locked the
folder for the whole network listing (17–35 seconds on a rate-limited Google
Drive), so other programs opening files there had to wait. **Ctrl+R** still
reads the folder from the cloud at once.

## Install

```bash
sudo apt install ./panero_0.1.0.preview.10-1_amd64.deb
```

Restart Panero after installing.

## Tested

- ctest (7 suites) and 16 cloud security tests.
- `dev/scripts/gui-cloud-freeze-test.sh`: stand-in drive under Xvfb, rclone
  stopped, 19 steps (browse, open a file, right-click menu, Ctrl+R, Up, the
  sidebar, the 30-second timers): the window never waits for the drive.
- strace of a normal session: accesses to the drive from the window's thread
  went from 163 to 5: three from the right-click menu on a file, two inside
  KDE's folder lister when the folder tree lists a folder (once per folder,
  right after its listing arrived).
- `dev/scripts/gui-cloud-test.sh`: path bar, Up stops at the top, Rename,
  folder badge.
